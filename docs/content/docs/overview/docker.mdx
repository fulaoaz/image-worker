# Docker Deployment

## Use the published image

```bash
git clone git@github.com:fulaoaz/image-worker.git
cd infinite-canvas
docker compose up -d
```

Open `http://localhost:3000`.

## Build locally

```bash
docker compose -f docker-compose.local.yml up -d --build
```

## Documentation image

The documentation in `docs/` is a separate Next.js standalone application with server capabilities.

```bash
cd docs
docker compose up -d
```

To build it from the current source:

```bash
cd docs
docker compose -f docker-compose.local.yml up -d --build
```

The application container serves the Vite app and its small configuration API. Canvases, My Assets, generation history, and user-provided API keys remain in the browser by default, while prompt repositories are fetched directly by the frontend.

## Server-managed model providers

For a shared deployment, create a `.env` file beside `docker-compose.yml` before starting the container:

```dotenv
ADMIN_TOKEN=replace-with-a-long-random-token
```

Then open `/admin`, enter that token, and add the providers and models you want users to use. The server writes the configuration to `data/ai-model-channels.json`, which is mounted as a Docker volume by the default Compose file. API keys stay in that file and requests are forwarded by the application server; browsers receive model names and capabilities only.

You can also define an initial JSON provider list with `AI_MODEL_CHANNELS`, but after the first save in `/admin`, the saved data file takes precedence.

## Optional analytics

No analytics are enabled by default. A deployment can enable GA4, Baidu Analytics, or both at runtime:

| Variable | Description |
| --- | --- |
| `ANALYTICS_GA4_ID` | Google Analytics 4 measurement ID (`G-XXXX`) |
| `ANALYTICS_BAIDU_ID` | Baidu site ID, the hash after `hm.js?` |

```yaml
services:
  app:
    image: ghcr.io/fulaoaz/image-worker:latest
    ports:
      - "3000:3000"
    environment:
      ANALYTICS_GA4_ID: G-XXXXXXXXXX
      ANALYTICS_BAIDU_ID: e8263761cc5c32f5f7a855b8203b965a
```

SPA route changes automatically report page views to enabled providers. Only configure analytics IDs on sites you control, and do not commit them to the repository.
